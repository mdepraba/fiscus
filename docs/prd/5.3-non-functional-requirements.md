# 5.3 Non-functional requirements

Memory is the binding constraint. Once Apion is gone, the 1 GB host has about 440 MB of headroom at idle. Any other process on the same host comes out of that headroom (A-01).

**Memory budget on the 1 GB host, after Apion is decommissioned**

| Component | Budget (RSS) | Basis |
| --- | --- | --- |
| OS (LXC, no Docker daemon) | 150 MB | [Apion PRD 07](https://github.com/mdepraba/apion/blob/main/docs/prd/07-platform-architecture-and-operations.md) |
| PostgreSQL 18 | 200 MB | Apion's limits: 160 MB shared buffers, 20 connections |
| Fiscus | 180 MB target, 256 MB hard cap | NFR-01 |
| Caddy and Tailscale | 50 MB | Estimate, measured at Gate A |
| Headroom at idle | about 440 MB | 1,024 MB minus the rows above |

While Apion still runs (180–280 MB), headroom is about 160–260 MB.

| ID | Category | Requirement (measurable) |
| --- | --- | --- |
| NFR-01 | Memory | Fiscus RSS ≤ 180 MB at idle, with MemoryHigh 224 MB and MemoryMax 256 MB |
| NFR-02 | Memory | Planned idle RSS for the whole host ≤ 600 MB |
| NFR-03 | Performance | The app's first load ≤ 2 s on Chrome's "Fast 4G" throttling and ≤ 1 s when cached, measured with Lighthouse on a mid-range Android phone |
| NFR-04 | Performance | Private API list and budget calls ≤ 300 ms at p95 with 50,000 transactions |
| NFR-05 | Limits | No request allocates more than 32 MB; uploads stream to disk |
| NFR-06 | Availability | Best effort on one host with no availability SLA; a deploy restart takes ≤ 10 s |
| NFR-07 | Recovery | At most 24 hours of data loss; restore to a fresh VPS in ≤ 2 hours from the runbook; restore test monthly (FR-11) |
| NFR-08 | Security | Only Tailscale and the ingest path are reachable; PostgreSQL listens on localhost; SSH is key-only; security updates install daily |
| NFR-09 | Security | CSP `default-src 'self'` and `connect-src 'self'`; no third-party scripts, fonts or analytics |
| NFR-10 | Security | Secrets only in `/srv/fiscus/.env` with mode 0600; passwords, tokens and recovery codes stored as hashes |
| NFR-11 | Privacy | Application logs never contain file names or transaction notes; logs are kept 14 days |
| NFR-12 | Audit | The audit log records who (owner or token name), what and when, plus before and after values for settings, and is kept 1 year |
| NFR-13 | Idempotency | Every create endpoint is idempotent per BR-09 |
| NFR-14 | Rate limits | Ingest 60 requests per minute per token (BR-31); private API 600 per minute per token; sign-in per BR-29 |
| NFR-15 | Retention | Transactions kept indefinitely; trash 30 days; import files 24 hours; exports 24 hours; backups per FR-09 |
| NFR-16 | Offline | The phone app reads and writes offline per FR-36. The web app is online only: offline it keeps what it loaded, read-only, under an offline notice, and saves nothing (Q-08) |
| NFR-17 | Platform | The web app: the latest two versions of Chrome, Safari and Firefox, with nothing to install (Q-08). The phone app: Android 10 or later; iOS waits for Q-06 |
| NFR-18 | Accessibility | WCAG 2.2 AA in light and dark themes; every action reachable by keyboard |
| NFR-19 | Localization | English UI; amounts shown as "Rp 25.000"; dates as "29 Sep 2026" in the device's timezone; Bahasa Indonesia later |
| NFR-20 | Maintainability | Boundary check, type check and tests pass in CI before every deploy; the host never builds |
| NFR-23 | Security | The phone's copy is encrypted at rest, and its token lives only in the phone's secure store. Revoking the token stops sync at once (FR-34) |
| NFR-24 | Memory | A full pull of 50,000 transactions keeps Fiscus within NFR-01: pull streams pages of about 1,000 rows (FR-40) |
| NFR-25 | Compatibility | The sync format is versioned and only gains fields, and enums only gain values, so an older phone build keeps syncing |

NFR-21 and NFR-22 are in [5.4](5.4-repository-layout.md).
