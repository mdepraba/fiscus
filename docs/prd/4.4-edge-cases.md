# 4.4 Edge cases & error handling

| ID | Scenario | Expected system behavior | User-facing message |
| --- | --- | --- | --- |
| EC-01 | Double tap on Save in quick entry | The client id makes the second request a no-op | — |
| EC-02 | A change made offline on the phone is pushed twice after a network timeout | The mutation's id returns the first result, and a create whose id already exists answers applied; one record exists (FR-39) | — |
| EC-03 | A script retries a create after a timeout | The same `Idempotency-Key` returns the original response | — |
| EC-04 | The same transaction is edited in two tabs, or on the web and on the phone | Each save carries the version it loaded, and a stale save is refused. The web app shows both versions; the phone app first merges field by field and asks only about a field both sides changed (FR-42) | "Changed elsewhere. Review both versions." |
| EC-05 | An import overlaps data already in Fiscus | Overlapping rows are flagged per BR-07 and skipped by default | "12 possible duplicates will be skipped" |
| EC-06 | A DD/MM file is imported as MM/DD | The preview shows the first 10 parsed dates and flags future dates or any day-month swap it can detect | "Check the date format" |
| EC-07 | A lunch is logged at 00:30 while travelling across timezones | The date follows the device's timezone at entry (BR-04); the list shows the zone when it differs from the current one | — |
| EC-08 | The next payday falls in a year with no holiday list | Budget warns; paydays are worked out with Monday to Friday only | "Holidays for 2027 are missing" |
| EC-09 | A holiday added later moves an upcoming payday | Upcoming cycles are recomputed; the open cycle's end date moves; transactions are reassigned by date | "Pay cycle dates changed" |
| EC-10 | Budget items total more than expected income | Saved with a warning | "Budget exceeds income by Rp X" |
| EC-11 | Free capacity is zero or negative | The afford check returns BELUM | "Not reachable at current capacity" |
| EC-12 | Days 1–6 of a cycle | Budget and afford results carry a warning | "Projections settle after day 7" |
| EC-13 | An ingest token leaks | Revoke it; Review offers "Trash all from this token since a date" | — |
| EC-14 | One invalid item in an ingest batch of 100 | The whole batch is refused with 422, listing each invalid item | Per-item reasons in the response |
| EC-15 | A public request uses GET, another path or no token | Other paths and methods get 404; a missing or invalid token gets 401; the body is never echoed | — |
| EC-16 | The database is down | The web app shows a banner and saves nothing; the API returns 503 with Retry-After: 30; the phone app keeps working from its copy and holds its queue | "Fiscus can't reach its database. Retrying." |
| EC-17 | Disk usage passes 85% | Uploads are refused; an alert email goes out | "Server disk nearly full" |
| EC-18 | Backblaze B2 is unreachable | Retries 3 times, 15 minutes apart, then alerts | Alert email |
| EC-19 | A recurring job runs twice after a restart | The rule-plus-cycle key blocks a second transaction (BR-33) | — |
| EC-20 | Password, second factors and recovery codes are all lost | Recover with the server reset command over SSH (FR-05); without SSH, use the VPS provider's console, per the runbook | — |
| EC-21 | First run: no transactions or cycles | Each page shows one line of guidance and its main action | "Import from Money Manager to get started" |
| EC-22 | The ledger reaches 50,000 transactions | Lists paginate at 200 per page with server-side filters, within NFR-04 | — |
| EC-23 | The phone has not synced for longer than tombstones are kept (BR-36) | Pull gets 410 `cursor_expired`. The phone pushes its queue first, then downloads everything again; no waiting change is lost | "Downloading your data again" |
| EC-24 | The phone edits a transaction that was trashed on the web | Push rejects it with `transaction_trashed`; the phone offers Restore and apply, or Discard | "This transaction was trashed elsewhere" |
| EC-25 | A queued change is refused, such as a transaction whose category was deleted on the web | It waits in "Couldn't sync" with the reason, and the changes that depend on it wait with it (FR-41) | "Couldn't sync: Category is no longer active" |
| EC-26 | The phone is lost or stolen | Revoke its token in Settings › Tokens; push and pull answer 401 from then on. The copy on the phone is encrypted (NFR-23), and the app can be locked (FR-44) | — |
| EC-27 | A slow database transaction commits after a newer one | Pull returns only rows below the watermark of the oldest running transaction, so the slow one's rows come with the next pull and none is skipped (FR-40) | — |
| EC-28 | The phone cannot reach Fiscus: no signal, or Tailscale off | The phone works from its copy, queues its changes, and syncs when the server answers again (A-15) | "Waiting to sync" |
