# 4.2 Business rules & validation

All money is whole rupiah; income and budget amounts live in settings, never in code.

**Transactions and API**

| ID | Rule | Applies to | Behavior when violated / message |
| --- | --- | --- | --- |
| BR-01 | Amount is a whole number of rupiah from 1 to 10.000.000.000; an amount in another currency is a whole number of its smallest unit in the same range (A-11) | Transactions, import, API | Refused: "Amount must be a whole rupiah value from 1 to 10 miliar" |
| BR-02 | Type is Expense, Income or Transfer. Expense and Income need a category; Transfer needs two different accounts and no category | Transactions | Refused, naming the failing field |
| BR-03 | Account and category must exist and be active | Transactions, import, API | UI refuses; import lists a row error; API returns 422 per item |
| BR-04 | A transaction's date is its calendar date in the device's timezone at entry, or the offset given in the API payload; the offset is stored with it | Transactions, API | API item without an offset is invalid: "Date must include a timezone offset" |
| BR-05 | Imported TSV rows carry a date without a time; that date is used as is | Import | — |
| BR-06 | A date may be at most 1 day in the future | Transactions, API | Refused: "Date is in the future" |
| BR-07 | A possible duplicate has the same date, account, amount (in the account's currency) and type, and a note equal after ignoring case and spaces, compared with Confirmed and Unreviewed records and rows in the same file | Import, API, quick entry | Flagged, never dropped: import preview marks it (default Skip); other creates save it with a "Possible duplicate" tag |
| BR-08 | Note up to 200 characters; description up to 1,000 characters; up to 5 tags of 30 characters each | Transactions | Refused, naming the limit |
| BR-09 | `Idempotency-Key` is 8–64 characters and kept 24 hours per token | API | Missing: 400; same key with a different body: 422 |

**Pay cycles and budgets**

| ID | Rule | Applies to | Behavior when violated / message |
| --- | --- | --- | --- |
| BR-10 | A cycle runs from payday to the day before the next payday. Payday is day 25, moved to the previous working day when it falls on a weekend or holiday | Cycles | — |
| BR-11 | Working days are Monday to Friday, minus the holidays listed for that year | Cycles | Year missing: warning (AC-15.2), and working days count Monday to Friday only |
| BR-12 | Cycle income = the sum of the owner's income lines, each a name and an amount per cycle; a negative line is a deduction. Working days do not affect income | Budget | — |
| BR-13 | A transaction belongs to the cycle whose dates contain its date (BR-04) | Budget | — |
| BR-14 | Spent per item = sum of Confirmed and Unreviewed transactions matching the item's rules. Transfers count only where a rule names them (Investasi: transfers to Stockbit or Pluang); other transfers never count. Expenses that match no item go to Lain-lain (budget 0, flexible) | Budget | — |
| BR-15 | Projection, with d = days elapsed including today and D = days in the cycle: Daily = spent ÷ d × D; Weekly = spent ÷ ⌈d ÷ 7⌉ × (D ÷ 7); Fixed = max(spent, budget); Minimum = max(spent, minimum); Reserve = budget. Closed cycles use d = D | Budget | — |
| BR-16 | Reserved = max(budget, projection) for a locked item; projection for a flexible item | Budget | — |
| BR-17 | Free capacity = cycle income − sum of reserved | Budget, afford check | — |
| BR-18 | Money math uses integers; each item's projection is rounded half up to the rupiah once | Budget | — |
| BR-19 | One-off purchase: AMAN when capacity ≥ price × 1.15; KETAT when price ≤ capacity < price × 1.15; BELUM when capacity < price | Afford check | — |
| BR-20 | Monthly cost: the same statuses with a 1.5 buffer, using the lowest capacity among the open cycle and up to 3 previous closed cycles | Afford check | No closed cycle yet: result marked "Low confidence" |
| BR-21 | A BELUM result shows shortfall = price − capacity, and cycles to save = ⌈price ÷ capacity⌉ when capacity > 0 | Afford check | Capacity ≤ 0: "Not reachable at current capacity" |
| BR-22 | The buffers 1.15 and 1.5 are settings | Afford check | — |
| BR-23 | Edits to budget items and income lines apply to the open cycle and later cycles. When a cycle closes, its configuration (items, amounts, income lines) is snapshotted | Budget | — |
| BR-24 | Editing a transaction in a closed cycle changes that cycle's actuals in reports, not its configuration snapshot | Budget, reports | — |
| BR-25 | A budget item has an amount ≥ 0, one projection type of the five in BR-15, and a locked or flexible flag | Settings | Refused, naming the field; a total above expected income only warns (AC-15.3) |

**Lifecycle, limits and schedules**

| ID | Rule | Applies to | Behavior when violated / message |
| --- | --- | --- | --- |
| BR-26 | Trashed transactions are kept 30 days, then purged permanently | Transactions | — |
| BR-27 | An import file is at most 10 MB and 100,000 rows; a committed import can be rolled back for 7 days | Import | Too large: "Max 10 MB or 100,000 rows"; late rollback: "Rollback window closed" |
| BR-28 | A token has at least one scope, a name, and an expiry of at most 365 days; its value is 32 random bytes, shown once | Tokens | Refused, naming the field |
| BR-29 | 5 failed sign-ins within 15 minutes lock sign-in for 15 minutes | Auth | "Too many attempts, try again at HH:MM" |
| BR-30 | An ingest batch holds 1–100 transactions in at most 256 KB and is accepted or refused as a whole | Public ingest | 422 listing each invalid item's index and reason |
| BR-31 | Ingest allows 60 requests per minute per token | Public ingest | 429 with Retry-After |
| BR-32 | Categorisation rules match note text (case-insensitive contains), with an optional account and time window, in list order; the first match wins; rules apply on create only, never to existing records | Categorisation | No match: values stay as sent |
| BR-33 | A recurring rule creates at most one transaction per cycle | Recurring rules | Second run: no-op |
| BR-34 | Scheduled jobs and cycle opening use the server timezone setting, default Asia/Jakarta (A-10) | Scheduler | — |

**Sync and pairing**

| ID | Rule | Applies to | Behavior when violated / message |
| --- | --- | --- | --- |
| BR-35 | A sync push holds 1 to 100 mutations, applied in the order sent. Each mutation's id is a UUIDv7 and its idempotency key (BR-09) | Sync push | A batch outside the limit is refused whole with 422 |
| BR-36 | Tombstones of purged rows are kept 90 days. A pull cursor older than the oldest one kept cannot be served | Sync pull | 410 `cursor_expired`; the phone downloads everything again (EC-23) |
| BR-37 | A pairing code works once and only for 10 minutes | Pairing | Refused, and no token is made: "This code has expired. Show a new one." |
| BR-38 | Every mutation is checked by the same rules as its REST endpoint (BR-01 to BR-09, BR-25), whatever the phone checked first | Sync push | Rejected with the rule's violation code (EC-25) |
