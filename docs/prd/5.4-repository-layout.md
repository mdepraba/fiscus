# 5.4 Repository layout

Fiscus lives in one repository. The server deploys as one process, so one repo keeps a core change and the module change that needs it in a single commit, with no internal packages to version. The phone app lives there too, so a rule, its Dart copy and its shared test cases also change in one commit (ADR-0002, Q-01).

```text
fiscus/
├── apps/
│   ├── api/            Nest entry point; loads each module's manifest
│   ├── fiscus-web/     the web app: shell, navigation, palette; its screens load on demand
│   └── fiscus-mobile/  the phone app, in Flutter: its own Dart rules, the copy of the data, and sync
├── libs/               core: the platform every module plugs into
│   ├── api/            auth, tokens and pairing, registry, jobs, files, events, audit
│   ├── db/             database client, migration runner
│   └── ui/             design system, shell kit, and the platform screens
├── modules/
│   └── fiscus/
│       ├── contracts/  the only part other modules may import; fixtures/ holds sample sync bodies
│       ├── domain/     pay cycles and budget math, framework-free; cases/ holds the shared test cases
│       ├── api/        Nest module and the "fiscus" schema, sync included
│       └── web/
├── deploy/             systemd units, Caddyfile, backup scripts, PostgreSQL config
├── tools/              boundaries/, the checker copied from Apion; secrets/; the design tokens script
└── docs/               this PRD, decision records, restore runbook
```

**Rules**

- About 10 Nx projects: 3 apps (the server runner, the web runner and the phone app), 3 core and 4 module projects. A folder becomes its own project only when it needs its own boundary.
- The phone app is Dart, with a `project.json` instead of a `package.json`. It imports no TypeScript project, and its tests read only `domain/cases/` and `contracts/fixtures/`. Its CI job runs only when it, or the `fiscus` domain or contracts, is affected.
- Every project is tagged `scope:<module>` and `type:app|core|contracts|domain|api|web`; an untagged project fails CI.
- Modules import each other only through `contracts`. `domain` imports no framework; core (`libs/`) imports no module.
- Nothing personal goes in the repo: salary, budget amounts and secrets live in database settings or `/srv/fiscus/.env`. The repo is private by default.
- A module moves to its own repo only when it must deploy separately, gets another owner, or goes open source.
- If most module changes also edit `libs/`, core is doing module work and that logic moves back into the module.

| ID | Category | Requirement (measurable) |
| --- | --- | --- |
| NFR-21 | Build | CI uses Nx `affected` with caching and finishes in ≤ 5 minutes for a single-module change |
| NFR-22 | Bundle size | The web app's first-load JavaScript ≤ 200 KB gzipped; each module's screens load only when opened |
